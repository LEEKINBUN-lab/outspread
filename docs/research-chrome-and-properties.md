## 二、判决

### 1 · 透明圆角悬浮窗 —— 做，且要给"纸还是直角"一个说法

直角那条规矩的**对象是纸**（便签＝纸片，纸没有圆角、也不该是半透明的）。浮层不是纸，是界面上的玻璃。所以：

- 便签：直角 + 纸影，不动。
- 浮层（键位清单、以后的属性面板、右键菜单）：**圆角 + 亚克力 + 阴影**。
- 圆角值写成**一处令牌**（`Chrome.Radius`），不许每个浮层各写一个数——"别拿常数糊"针对的是散落的常数，不是 8 这个数本身。

实现边界（WinUI 3 投影里查过）：`DesktopAcrylicBackdrop` 只服务 `Window`，给不了 `Popup`；`Popup` 自己没有 `CornerRadius`。**原计划"Popup 里放一枚 Border{CornerRadius, AcrylicBrush}"已作废**——理由不是样式而是取证：`Popup` 是另一个顶层窗口，`outspread shot`（渲染 BoardArea 那棵视觉树）拍不到它，于是"圆角 8、透 94%"会变成一句没有读数的断言。现在三处浮层都挂在 BoardArea 自己的树里，`outspread shot --panel filter`／`cheat` 能把它拍进 PNG，圆角、底色、字能不能读都能现量。`ThemeShadow` **已试并已挂上**（10-12）：前提正是"浮层与宿主同一棵 visual tree"，所以树内的 Border 挂得住；`UIElement.Shadows`／`ContainerVisual.Shadows` 这一版投影里没有（编译器拒），过来的是 `UIElement.Shadow` ＋ `ThemeShadow`，旋钮只有一个——抬多高（`Lift.ZPx=24`）。它复现的是菜单那一发的**剖面**（现读：两侧 1px 处比地面暗 5.5%，基准 5.6%；下方 18%，基准 14%；上方留 6% 余影，基准为 0），不是它借来的皮——借不到：现读 `MenuFlyoutPresenterBackground`＝`#00000000`，白与影是系统 popup 宿主画的。

**10-12 第二次打回之后补的一条（阴性，别再试第二次）**：他说「从字体、排版到动画都完全不一样…要让人感觉只是换了一下文字」。量的结果：数早就都对（行 32、字 14、字距边 16），差的是**类型系统**——菜单只有一种线，我们有三种（14 正文、12 加粗带字距的分节、键帽）。分节与键帽撤掉之后，试过**直接用菜单那枚行控件**，在 WindowsAppSDK 2.5.1 上失败，四条读数：裸 `MenuFlyoutItem` 进树 ⇒ `RenderTargetBitmap.RenderAsync` 永不返回（浮层就拍不到了，而「拍得到」正是它留在树里的唯一理由）；放进 `MenuFlyoutPresenter` 能画，但行盒 39.62（真菜单 32）、自动宽塌成 240、右列在模板里是 `Collapsed`（现读 `『2』Collapsed/12px/0w`），而这版投影没有 `IsKeyboardAcceleratorTextVisible` 可以打开它。⇒ **只能复现，不能借用**；但这一发把复现要用的墨色从平台自己身上量了下来：正文 rgb(27,27,27)、右列 12px/rgb(96,96,96)、禁用档 rgb(161,161,162)。动画那一格：`PopupMenuThemeAnimation` 现读＝未定义（它在 popup 宿主那一侧），所以挂平台给弹层的 `PopupThemeTransition`——只证到「挂上了」，播得对不对归他的眼睛。

令牌落点：`src/Outspread.Core/Chrome.cs`（半径 8、面板填充＝板底、alpha 0.94、发丝边浅 16%／深 34%），`ChromeStyling.ApplyFloatingChrome` 把这三个值打到 Border 或 Button 上。`NoteType.PropsSize/PropsBand` 与 `Chrome.Radius` 各只有一处定义。

### 3 · markdown —— 做，规范站在我们这边

范围定"卡片里真读得出来的那几样"：`#`~`###` 标题（只改字号字重）、`**粗**`、`*斜*`、`` `码` ``、`-` 列表、`- [ ]` 待办、`[文字](url)`、`> 引用`。
**不做**：表格、内嵌图片、HTML、脚注、嵌套列表超过一层。

三条不可省的设计：
- **编辑时显示原文，不编辑时才渲染**。所见即所存；渲染态编辑要做双向转换，那是另一类 bug 的温床（Obsidian/Excalidraw 走的都是这条路）。
- **落盘仍是那串 markdown 原文** ⇒ 与 Obsidian 互通不变（规范本来就允许）。
- 卡片高度必须按**渲染后**的行高量：标题会让首行变高。这和 S1 那行"字号/行距/内边距成对走"是同一件事，得一起改，否则第一版会出现"渲染后溢出被截"——正是刚修过的那类缺陷。

### 4 · 标签和日期抽成属性 —— 三个去处，判决是第三个

| 去处 | 判 | 为什么 |
|---|---|---|
| a. 节点里加 `"tags":[...]`、`"due":"2026-10-09"` | **不选（现在）** | 上面第 3 条：规范对未知字段无约定，Obsidian 可能丢；文件是三方共享的，丢数据不可恢复 |
| b. sidecar 另存一份 | **不选为主** | 文件不再自描述：agent 读一个 `.canvas` 看不全这块板；同步层要处理两份文件的合并 |
| c. 留在正文，但换成**不可能撞车的形状**：一行 `@due(2026-10-09) @tag(周会)` | **选它** | 仍是 `text`（任何 app 不会丢）；形状严格（`@名字(值)`，不像 `#xxx` 会撞上 hex 颜色、话题标签、C 语言注释等）；UI 上把这行**从正文里摘出来显示**——卡片上不出现这串字，只出现左缘色条和一行属性；编辑时可见可改 |

代价说清楚：**c 仍然是"和正文合在一起"**，只是换了一个不会误认的形状。你说"直接和正文合在一起容易错误识别"——现在会误认的根源是 `#` 这个字符本身歧义（`#ff6b6b`、`#周会`、`# heading`），`@due(...)` 没有这个歧义。

如果你要的是**真字段（a）**，那前置条件是一次实测：拿一个带未知字段的 `.canvas` 让 Obsidian 打开并存盘，看留不留。这个我可以做，但要装 Obsidian（一次性、可卸）。**你说走 a 还是 c，我就照那个做**；默认我按 c 实现，因为它不需要赌别人的实现细节。

兼容：现在板上的 `#due:` / `#tag` 继续能读（你的旧板子不坏），新写的走 `@due()`；"写错的日期必须标出来"那条规则原样搬过来。

**实现时补上的一条（原判语没写到）**：token **只有在一整行都只由 token 组成时**才算属性。少了这条限制，任何在正文里引用这套写法的格子都会把自己的例子吃掉（`#6ccda3` 那次是同一类事故的另一个形状）。代价说清楚：写在行内的 `@due(2026-10-09)` 不生效，但它**照样显示在原处**——所见即所存，不是静默丢弃；属性行的形状就写在漏斗面板的最底下，问的地方和答的地方是同一处。

显示侧：token 行从卡片正文里摘掉，换成卡片底下一行读数（`逾期 10-09 · #周会`，`NoteMarks.Readout`）。这一行的高度由 `NoteType.PropsBand` 一处给出，量自动高度的一方与画卡片的一方读同一个数——否则最后一行被切是老账。

已实现（Core 侧 274 项测试通过、Board 编译无错），**界面读数待一次新 build 的截图**：他的实例还开着，输出目录被锁，这一版没能落到运行的那一版上。

### 5 · 左下角那排标签 —— 已按判决撤掉

别家怎么做（可核对）：tldraw **没有**常驻标签条（筛选在菜单与选择里）；Miro 是 view-only filters，**只在激活时出现**一条顶部横幅并写明"正在筛选"；Notion 把 tag/date 当属性，筛选发生在**视图**（表/看板/日历）里，白板面上不常驻；Obsidian Canvas 完全没有这一层。

判决：
1. 常驻的 chip 排撤掉。"有日期"这件事**卡片左缘那条色条已经说完了**，不需要第二处。
2. 筛选入口挪到右下角那组缩放按钮旁边一枚漏斗图标；**激活时**才在板顶出现一条窄横幅：「只看 #周会 · 15 格中的 1 格 · 点这清除」。
3. 为什么现在这排"AI 感重"：四枚描边胶囊 + 计数，形状和板子上任何真实物件无关，而且永远在场——它把数据摘要当成了主界面在说话。改法就是把它降级成"只在有事时出现的状态"。

落成的样子（本轮）：`MarkPanel` 那排常驻胶囊已从 XAML 删掉；漏斗在右下角那组按钮的最左一枚，点开一枚竖排浮层（逾期／今天／以后／日期读不出 各带当帧计数，下面是有人的标签清单，最后是属性行的写法）；横幅 `FilterBanner` 是板顶居中一枚浮层按钮，文案就是判决里那句「只看 #周会 · 15 格中的 1 格 · 点这清除」，点它＝清除。计数为 0 的档不占一行，但**正在被这一档筛着时留着**，否则"取消"这一格会凭空消失。`Esc` 先收这一层面板、再管选中；按板子任何一处也收；窗口失活时两张浮层一起收起（按住 Tab 的手不见了，清单不能留在板上）。



### 6 · 牌子（日期／标签）该长什么样 —— 10-12 调研与判决

他原话：「调研并优化标签的样式，一个方框看起来很廉价。」当时实物是：卡片左下角那排牌子＝**1px 实线方框、直角、无底色**（编辑器里那排＝无框、7% 软底、直角——同一件东西两份画法）。

一手事实（都能回查，来源在括号里）：

| # | 事实 | 来源 |
|---|---|---|
| 1 | Material 3 的 chip：`container_height 32dp`、`container_shape` = cornerSmall（**8dp**）、flat 态描边 1dp | material-components-android `chip/res/values/tokens.xml` |
| 2 | Fluent 2 的 Tag：`borderRadiusMedium` = **4px**，高 20/24/32，默认边是 `colorTransparentStroke`——**槽位在、色透明** | fluentui `react-tags/.../useTagStyles.styles.ts`、`tokens/src/global/borderRadius.ts` |
| 3 | Carbon 的 Tag：高 18/24/32、`border-radius: 16px`，且每条非可选 tag 都写死 **`border: 0`** | carbon `packages/styles/scss/components/tag/_tag.scss` |
| 4 | Ant Design 的 Tag：**4px** 圆角、12px 字号、固定 8px 横内距；文档建议弱层级时用 `bordered={false}`；它的 Badge status 是 **6px 点 + 文字**（无容器） | antd `components/tag/style/index.ts`、`components/badge/` |
| 5 | GitHub Primer `.Label`：12px 半粗、`line-height:18px`、`padding: 0 7px`、`border-radius: **2em**`（胶囊），边是 1px 透明 | primer/css `src/labels` |
| 6 | **日期与标签是两种东西**：Trello 的到期是一枚整块换色的状态徽牌（官方文案：黄＝快到期、红＝刚到期、浅粉＝已逾期、绿＝完成），标签是色块；GitLab／Microsoft Planner／Asana 的到期是**文字自己变红、没有盒子**；Todoist 把颜色挂在**标签名**上而不是盒子上 | support.atlassian.com/trello（dates、labels）、docs.gitlab.com due_dates、support.microsoft.com Planner、forum.asana.com（overdue red）、todoist.com help「introduction-to-labels」 |

**判决**（落成第 5 种形状，不在原四版里）：

1. **日期＝状态点（6px）＋文字，没有容器。** 点的颜色就是卡片左缘那条到期色条的同一枚——一件事在一格上只说一种颜色。
2. **标签＝无描边胶囊**，半径＝带高一半，底色是卡片自己那支墨的 8%。
3. **两种牌子共用同一带高、同一字号、同一字重**，所以它们是"一套里的两种"，不是两套语法（调研里对第 2 种方案最实在的警告就是：两种语法若重量不严格相等，看着像出错了而不是像设计）。
4. **悬停才上色到 16% 并长出 ×**：调研点名的唯一实质风险是"没有盒子就看不出可点"，而我们要能点掉它。这跟 Fluent 留一枚透明描边的思路是同一件事。

**代价与边界**：① 淡彩卡上叠色调会撞，所以底色压在 8%（各家都在 18% 以下）；② 数字等宽（`font-variant-numeric: tabular-nums`）在 WinUI 3 的 `TextBlock` 上没有那一面（`Typography` 不在投影里），计数列仍会随位数抖，这条从原型继承、本轮没解决；③ 直角那条规矩的对象是**纸**，牌子是贴在纸上的界面件，所以它可以是圆的——与浮层同一判据。

**没测到的一格**：悬停态（上色与 ×）只有真鼠标移上去才出现，`shot` 拍不到，本轮没有移上去。

## 四、标题栏＝一块板一个标签（2026-10-21）

### 判决

1. **取证通道先补，再上界面件。** `outspread shot` 原来只渲染 `BoardArea`（板面），标签条在它外面，于是"标签长什么样"会是一句没有读数的断言——正是 §二·1 为 `Popup` 花掉一轮的那件事。现在多一档 `--mode chrome` 渲染 `Root`；**板面那一档的目标一个字不动**，已有的对比读数（点阵、板底、浮层）都锚在 `BoardArea` 上。mode 与 panel 可叠加（10-22 起是 `--mode chrome --panel rename`，拍"标签条＋行内改名输入框"同框；旧的 `boards` 浮窗已删）。
2. **一块板一个标签，一块板只允许一个标签，最后一块不给关。** × 仍画在那儿（皮是平台的，不为一枚按钮去重模板），按下去只说为什么：回执那句「最后一块板不给关：要收这个窗口，按右上角那枚 ×」。
3. **切板＝先交回盘，再指新的。** `FlushCurrentBoard()`（停那半秒的定时器 → 存 sidecar → `SaveNow()`）→ `LoadBoard(path)`。同时把 `LoadBoard` 改成"读完并解析成功才动 `_boardPath`/`_document`/`_baseJson`"：一块读不懂的板子不该把窗口切过去，那等于让人以为自己在改这块板而屏幕上还是上一块。开不成时标签条退回真的那块板。
4. **撤销历史与筛选切走即弃，pan/zoom 进 sidecar**（那份文件本来就一块板一份）。这不是省事：`_pendingSnapshot` 里躺着的是上一块板的整份 JSON，留着它，下一发撤销会把另一块板写进这一块。
5. **皮全交给平台**（**已被 2026-10-22 的浏览器式改皮覆盖**，见下一节）：直角从 XAML 里那两枚资源键（`ControlCornerRadius=0`）继承，不为标签条开第二种画法，也不重模板。新板块／打开已有那一层浮窗仍走 `ChromeStyling.ApplyFloatingChrome` 与 `PanelKit` 的行——它是浮层，不是标签条。

### 代价与边界

- **agent 的取证通道只跟当前那一枚标签**：`outspread shot --board X` 找的是 X 那根管道，切走以后管道归了别的板，会报"没有运行中的这块板子"。`list`/`patch`/`validate` 直接读文件，不受影响。这一条是"一个窗口处理一件事"的必然形状，不是缺陷，但写在这里免得下次当成回归。
- sidecar 格式没扩，所以撤销栈不跨切板；要跨就得动安卓端与 agent 都读的那份文件（`docs/sync-contract.md` 的三形状契约）。
- 命令行可以一次点几块板（第一块是启动那块，其余开成标签）。这一条不只是入口：三枚标签的标签条只有真开着三块板才拍得到，取证走的也是它。
- **未测（真手才够得着）**：在标签条空白处拖窗口；真键盘的 `Ctrl＋T`／`Ctrl＋W`／`Ctrl＋PageDown`／`Ctrl＋PageUp`（自检调的是方法，不走键位派发）；悬停态；系统那三枚按钮与标签条的实际重叠（PNG 不含非客户区，那一格只有 138 这个数）；标签多到溢出时的滚动。

## 五、筛选时组里没命中的折进命中那格（2026-10-21）

他原话：「组的框应该跟着便签走，如果筛选的话，把组里符合条件的筛选出来，然后组里其他不符合筛选的折叠/隐藏到符合条件的里面。鼠标移上去自动展开，动画效果要做好。」这一条的前提是 §四之前那一发（组框改为派生），所以顺序是先修框跟着走，再谈折叠。

### 判决

1. **折叠只长在画面上**：一枚 `TranslateTransform` ＋ 透明度，文档一个字节不写。这条不是洁癖——筛选把三格并到一处的样子要是写回文件，一次筛选就把便签的"真位置"同步给了手机（`boards/<名>.canvas` 是两端共读写的那份）。凭据两式：自检断言 `_document.ToJson()` 在折回／摊开前后逐字符相同；实物那块探针板在两发取证之后 mtime 与字节数都没变（`D:\Temp\outspread-fold\fold.canvas`，23:24 写入、829 字节，跑完仍是这个数）。
2. **锚点是命中者里的第一格（文档顺序）**，没命中的滑到它左上角重合处。**不发明"堆叠步长"**：藏起来的东西本来就不该露缝，而"这里藏了几格"由横幅明说（见 3）。
3. **藏起来的东西必须有一句**，否则筛选看起来像删了便签。原打算把「· 折起 N 格」写进框自己的标题那一格（同一件东西多说一句，不长出第二种控件），实物把它打回了：框贴着成员收之后，标题那 10 像素的边根本不够一行字站，**标签被自己的成员盖住**（`folded.png` 里看不见）。所以这句话改由**板顶那条横幅**说：「只看 #周会 · 3 格中的 2 格 · **1 格折进了组** · 点这清除」。框上那行仍然写（组框边够宽时看得见），但屏幕上"有一处说得出藏了几格"这件事由横幅负责，自检钉的是横幅。
4. **摊开的那几格仍然压暗**（0.22，它们没命中），并且框回到全组——藏的动作没了，"只框住命中者"这回事也没了。
5. **hover 的门要够大**：框本身**和**接住东西的那一格都算门，不要求人瞄一条 10 像素的边。`Esc` 先收这一层（一按退一层），手离开这扇窗口也收。

### 代价与没测到的一格

- **动画的中帧拍不到**：`shot --panel fold／unfold` 走的是 `animate: false` 那一档（直接把状态摆到位再排版）。理由是这条闸门不接受"等一会儿再拍"——中帧不是终态，而用固定等待换确定性是他明令禁过的。所以**动画本身是视觉债**，复现通道：打开那块探针板，右键菜单→筛选：日期与标签…→点 `#周会`，然后把鼠标移到那组上。
- **曲线只有平台的**：页面写 `cubic-bezier(0,0,0,1)`（进入）与 `(0.16,1,0.3,1)`（悬停），这一投影里喂不进任意贝塞尔（`CubicBezier` 在 `metadata/Microsoft.UI.Xaml.winmd` 里 0 命中），能给的只有 `CubicEase`。时长对得上，曲线是同族不是同一条——这一格也只有眼睛判。
- **hover-only 的可达性**：WCAG 1.4.13 要求悬停出来的内容可停留、可 hover 进去、可用 Esc 关掉。停留与 Esc 都做了，"可 hover 进去"天然满足（摊开的格子就在门里面）；但**没有键盘入口**——键盘用户目前只能靠"清除筛选"看全部。要补就是一枚"摊开这一组"的命令，本轮没做。
- **折进去的格子点不到**，所以不能直接拖走它：要先摊开。这是"藏起来的东西不该被误拖"的必然代价，写在 README 那一行里。
