操作条图标集比稿 · 四档

现在实物用的是 A 档（系统字形），他判"丑"的是那枚垃圾桶。四档用同一枚圆钮、同一套色、 同一组尺寸摆出来；每档下面写清来源、维护成本，以及选中后 1:1 搬到实物要动哪几行。

A · 系统原生字形（实物现在这档）

来源：Windows 自带  Segoe Fluent Icons / Segoe MDL2 Assets 码位表 （这里摆的是 People E716 / Color E790 / Delete E74D 三枚，码位以本机字表为准）。零文件、零授权、零维护； 代价是笔画与站位不受我们控制，且**换主题/换系统版本时字表会变**——他 10-23 判加号那枚 "全角＋字形不受控"就是同一件事。

换色那枚（E790）与组那枚（E716）在同一字表里笔画粗细不一致——这正是"三枚看起来不像一组"的成因。 要留在这一档，能做的只有换码位，改不了笔画。

B · 细线自绘（Lucide / Tabler 那一派）

来源：24×24 网格、1.5 描边、圆头线帽——与  Lucide（ISC）/ Tabler Icons （MIT）同一套规矩；下面这三枚是我们在仓里自绘的 SVG path（不引第三方包，不引运行时）。 维护成本＝三个 path 字符串；好处是三枚同一网格、同一粗细，缩放不塌。

落到实物：WinUI 里没有 SVG 运行时，这一档要用 PathGeometry（XAML Path 的 Data 串）画—— 和加号那枚"画出来的两根圆头细条"同一条路（他 10-23 选过的写法）。三枚各一段 path， 粗细/端点写死在令牌里，深浅两档共用。

C · 实心剪影（Fluent 填充派 / Material Symbols Rounded 那一派）

来源：同一网格但填色，视觉更"重"。好处是在淡底圆钮上更容易被看见；代价是三枚挤在一列时 显得闷，而且"删"填成实心红块会盖过它只是可撤销这件事的分量。

落到实物：与 B 同一画法（PathGeometry），只是 fill 不 stroke。若选这档，建议"删"不填红—— 保留细线红，只把组/色两枚填实，避免三枚一起变重。

D · 干脆不用图标（文字胶囊）

来源：把三枚圆钮换成一行小字（组 · 色 · 删）。判据是"图标认不出来时，字一定认得"—— 他 10-12 判漏斗按钮"看不懂是什么"删掉它，是同一条路。代价：操作条变宽、鼠标热点少一层直觉。

组 色 删

这一档不需要图标集，也就不需要维护；但它改的是操作条的形态，不只是图标。

我的推荐：B（细线自绘）。理由三条：① 三枚同一网格同一粗细，"不像一组"这一格从根上没了； ② 笔画不受字表版本影响（A 的那条风险是系统升级就变样）；③ 与加号那枚同一条画法，仓里已有先例， 不新增运行时。判据：缩到 16 还认得出各是谁——这一页只把"删"那一枚摆到 16 量过，另两枚要选这档时同法补一发再搬。 若他要的是"少写代码"，那就选 A 并只换垃圾桶那枚的码位——那是 5 分钟的改法，但改不了笔画不一致。
