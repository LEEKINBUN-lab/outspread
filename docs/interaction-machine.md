# 交互闭环 · 状态机设计

这份不是愿望清单，是**判据**：谁在这一发按键/按下里说话、说完之后板子必须落在哪个状态、以及"改了但没落盘"这种洞为什么堵住了。

## 〇、先说现状（本轮现读，带行号）

App 现在的交互不是没有，是**散在十个字段里**：`_marqueeing`、`_panning`、`_rightDrag`、`_nodeGesture`、`_resizeGesture`、`_editingId`、`_dragOver`，加 S5 才要动的 `unitMode`/`groupFocus`。每个输入口自己进去问一圈 `if (xxx is not null) return;`。这类形状已经咬过我们三次：静止右键弹菜单要先判 travel、端点把手和边拖抢同一发按下、编辑中不该显示选中态——**都是同一件事的三次**：没有"现在轮到谁"这个唯一答案。

键盘：只有 7 条（`MainWindow.xaml.cs:2357-2414`）——Esc、Ctrl+A、Ctrl+V、Ctrl+Z、Ctrl+Y、Delete、Ctrl+0。
右键菜单：6 项（`:1761-1805`）——颜色 6 档＋无色、叠放 2、删掉这 N 格、回到 100%、撤销『…』。
创建入口：双击空白＝新建并进编辑（`:1417-1433`）、Ctrl+V 粘贴、拖文件进来、`outspread add`。
**29 条命令里在 App 有落点的只有 4 条**（移到最前/最后、回到 100%、撤回、重做）。对齐 6 / 均分 2 / 堆叠 / 聚拢 2 / 连线 / 成组 / 拆组 / 复制 / 锁定 / 看到全部 / 看到选中 / 聚焦 / 查找 / 跳到邻格 / 骨架 3 —— 全树 grep 零命中（本轮查过，不是"没找到"）。

## 一、状态集（互斥，至多一个）

| 状态 | 谁持键盘 | 进 | 出 |
|---|---|---|---|
| `Idle` | 板面 | 无选中 | 按下格→`Selected`；按下空白→`Pointer(Marquee)` |
| `Selected` | 板面 | 有选中（永远是格子的集合；10-22 起组框不进选中，`Layer` 子状态随两层点击一起作废） | 命令、按下、双击 |
| `Pointer(op)` | 板面 | 一次进行中的手势，`op ∈ Marquee / Pan / Move / Resize / Connect`，**带 travel** | 松手→`Selected`/`Idle` |
| `Editing(id)` | TextBox | 双击格、F2、新建即编辑 | Ctrl+Enter/点到别处＝提交；Esc＝放弃 |
| `Finding` | 查找框 | 查找命令 | Enter 跳、Esc 关 |
| `Menu` | 菜单（模态） | 静止右键松手 | 任一项/点外面/Esc → 回原态 |

`Pointer` 只在 travel 过 4px 阈值后才算**开始**（`BoardGestures.DragThresholdPx`）。没过的按下不是手势，是一次"点"——这一条把现在散在各处的 `if (IsDrag(travel))` 收成一个地方。

## 二、迁移表（只列承重的那几行）

| 现态 | 事件 | 次态 | 副作用 |
|---|---|---|---|
| `Idle` | 按下空白·左 | `Pointer(Marquee)` | 记下 Shift/Ctrl＝加选还是换选 |
| `Pointer(Marquee)` | 松手·travel<4 | `Idle` | 清选中（除非修饰键） |
| `Idle`/`Selected` | 按下空白·右 | `Pointer(Pan)` | 记下起点 |
| `Pointer(Pan)` | 松手·travel<4 | `Menu` | 静止右键＝菜单，不是平移 |
| `Selected` | 按下格内·左 | `Pointer(Move)` 或 `Pointer(Resize)` | 由 `EdgeOf` 判：离边 ≤6 屏幕像素归那条边 |
| `Pointer(*)` | 松手 | `Selected` | **一个事务**：写文档→history→标脏 |
| `Selected` | 双击格 / F2 | `Editing(id)` | 编辑框从该格的当前文字起 |
| `Editing` | Ctrl+Enter / 失焦 | `Selected` | 提交＝一个事务 |
| `Editing` | Esc | `Selected` | 放弃＝**不产生事务**（history 不许多一格） |
| `任意` | 外部改动 | 同态 | 只并对方改的格；正在拖/正在编辑那一格不覆盖 |
| `任意` | 命令 id | 由注册表定 | 见第三节 |

## 三、命令注册表＝一份声明三处用

原型的 `CMDS`（`design/feel.html:2070-2101`）就是这个形状，理由写在它上面那三行注释里：**单字母快捷键按 WCAG 2.5.7 必须有替代输入面**。你给这版定的是"单键快捷先不做"，所以推论是硬的——

> **菜单就是那唯一的替代面，它必须能到达全部 29 条。** 现在 6 项的菜单不满足这一条，所以"先不做单键"不能顺手把命令也砍掉，只能把入口从键挪到菜单。

每条命令声明五件事，Core 里一个 record：

```
Id · 标题 · 键位(只允许 Ctrl/Alt 组合) · 合法状态集(Flags) · 前置条件(选中数/是否成组/有没有连线)
```

菜单、键盘派发、以后的按钮栏都读这一张表 ⇒ 加一条命令＝表里加一行，不改任何 `if` 链。

## 四、机器必须保证的五条不变量（每条都要有会抛错的测试）

1. **同一时刻至多一个键盘持有者**（`Editing`/`Finding` 期间板面键位一律不进）。
2. **没过 4px 阈值的指针动作不许产生事务**——history 里不许出现"点了一下"的空格子。
3. **改文档的唯一路径是事务**：Begin/End 成对，End 才 push history 并标脏 ⇒ 不存在"改了但没人知道"。
4. **不合法的命令要明着拒绝**：状态条写"对齐要至少两格（现在 1 格）"，不许静默 no-op。
5. **Esc 是纯放弃**：编辑/手势/菜单/查找的 Esc 都不许留下文档改动，也不许留下 history。

## 五、落地次序（每步都要能单独收口）

| 步 | 内容 | 判据 |
